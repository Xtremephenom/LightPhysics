# Known limitations — Phase 2

- The repository is an early studio substrate; no production package, distributable desktop app, engine bridge, Foundry, Verdict, MCP facade, or real dogfood game exists yet.
- The Phase 0 `lpd`/`lp` workspace wrappers, Core API walking skeleton, browser-served Studio Floor, Phase 1 kernel, and Phase 2 Forge/mock consult path are present; Electron packaging, engine bridges, providers, and model workers remain future surfaces.
- Phase 2's catalog contains only deterministic mock/fixture records. A `QUALIFIED` badge on those records means adapter/contract behavior on the recorded mock profile, never real model quality, latency, VRAM behavior, or hosted-provider availability.
- `docs/research/model-atlas-verified.md` labels the Phase 2 atlas rows `ASSUMED` or `DISPROVED` only where the repository has a conservative hypothesis or rejection; no real model row is qualified. Real primary-source/API research and Owner hardware runs remain required before widening claims.
- `corepack pnpm run forge-demo` uses the mock adapter, temporary storage, and a digest-only Ledger provenance record. It does not generate media or write a game repository.
- The offline root test uses Node 24's built-in runner on TypeScript files. Existing workspace packages use the pinned Vitest dependency; the root config remains reserved for the first root package suite.
- The pnpm lockfile covers the current workspace's TypeScript/test dependency graph; it is not a completed dependency-license audit or model-license clearance.
- uv is hash-pinned and qualified only for Windows x64 and Linux x64 Docker binary smokes; Blender is hash-pinned and qualified only for Windows x64 and Linux x64 Docker background smokes; Godot 4.7.2 is hash-pinned and its editor boot/check-only plus separately scoped headless project-import smokes are qualified only on Windows x64 and Linux x64 Docker; FFmpeg 9.0.2 is hash-pinned and its LGPL static version/lavfi smokes are qualified only on Windows x64 and Linux x64 Docker; the Docker bootstrap still runs in check-only mode for the remaining UNKNOWN entries.
- The Docker runtime is a service image, not a production release: it requires an operator-supplied `LP_TOKEN`, publishes only through an explicitly loopback host mapping, and contains no real model weights or provider credentials.
- `scripts/footprint.mjs` records host-specific cold-start and idle working-set observations while deliberately reporting `NOT_QUALIFIED`; the Windows report has no portable RSS value.
- The project license is MIT, but the dependency/tool/model attribution audit is not a commercial-clearance opinion; database binding, engine flags, model licenses, hosted terms, and remaining external tool research remain scoped by the Research Ledger and backlog.
- The committed-state rebuild proof requires a clean checkout because `scripts/verify-rebuild.sh` checks repository state before cloning; the Phase 2 proof is recorded in `docs/evidence/phase2/verify-rebuild.md`. It qualifies the reproducible build/test/runtime path only, not real models, hosted providers, GPU behavior, or creative quality.
